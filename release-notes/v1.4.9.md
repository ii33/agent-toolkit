# 通用 agent 工具集 v1.4.9

`@local/dsh-agentkit` —— 与翻译、模型无关的通用 agent 工具集，以 DSH 的 bundle + agent preset 形式分发。

这一版是**兼容性修复**：让 `generic`（通用环境）预设能在 DSH Desktop 0.2.2-rc.1 上正常挂载。

## 修了什么

**1. 预设子行配置跟随 0.2.2 的 `dsh-tool-subagent`**

0.2.2 把 `modelSelectionSettings` 拆成了 `modelSelection` + `modelDiscovery`，并彻底移除了 `backgroundMode`。
DSH 的 Config schema 会拒绝未知键，所以 1.4.8 的预设补丁在 0.2.2 上会让子行校验失败：

```diff
-              modelSelectionSettings: true
-              backgroundMode: continuable
+              modelSelection: true
+              modelDiscovery: true
```

**2. 移除 `tool-subagent-list-agents` 行**

0.2.2 的 `@deepseek-ai/dsh-tool-subagent-control` 不再导出 `./list-agents` 子路径
（`list_agents` 工具已并入主入口 `lib/index.js`）。保留这条子路径行会让预设名册审计报：

```
tool-subagent-list-agents (@deepseek-ai/dsh-tool-subagent-control/list-agents): never started
```

在 Web UI 上表现为预设卡片红色徽标「**加载失败**」——工具本身没丢，`list_agents` 仍由
`tool-subagent-control` 那一行提供。

**3. 兼容性说明更新**

`engines.dsh` 或 `@deepseek-ai/dsh*` 的 peer 才参与 DSH 的准入判断；
`@deepseek-ai/schemastery`、`react` 这类 peer 不参与，运行时不匹配也不会被拒绝。

## 升级

```bash
plugin_manager install_bundle <本目录 或 local-dsh-agentkit-1.4.9.tgz>
```

装完**重启一次** DSH Desktop。然后检查：

- 「通用环境」预设卡片不再出现「加载失败」徽标；
- 委派工具（`subagent` / `subagent_fork` / `list_agents`）仍然可用。

## 目标运行时

- DSH Desktop **0.2.2-rc.1**（schemastery 3.19.0 / cordis 4.1.0 / react 18）
- 0.2.1-rc.x 继续可用；更早版本未验证
