# 通用 agent 工具集 v1.7.0

`@local/dsh-agentkit` —— 与翻译、模型无关的通用 agent 工具集，以 DSH 的 bundle + agent preset 形式分发。

这一版修**配置与实际生效不一致**这一类问题：设置页改了、预设补丁没跟上，只能人工去 YAML 里改。

## 修了什么

**1. 设置页关掉能力后，预设能力表自动同步**（`lib/gate-reconcile.js`）

此前 `settingsGate()` 只在**注册时**拦截：关掉能力后工具确实不注册了，但预设补丁里的
`tools: [...]` 数组原样不动 —— 配置与实际生效长期脱节，只能人工删。

现在 `syncFromSettings` 写状态前先做对账：

- **只裁剪、不新增**：预设没声明的能力不会因为闸门开着就凭空加进来
- 闸门为 `undefined`（一个都没勾）时视为「未配置」，**绝不因此清空预设**
- 保持声明顺序，无变化时不写文件（幂等，不触发重载循环）
- 只动受管预设（`edits` / `presets` / `inject` 里出现的 id），其它预设不碰
- persona / suffix / complete 等字段原样保留
- 每次自动裁剪打一行日志，说明移除了哪些能力

**2. 能力清单改为动态求值**（`lib/capabilities-context.js`）

清单此前在 `apply()` 时算成静态字符串，旧会话持有旧对象，能力关掉后提示词里仍在宣传它。
改为 `text` 函数后，每轮组装都按当前能力重算；同时按注册层报告渲染，被让出/重入跳过的
工具不会出现在提示词里，「用 read 不要用 cat」这类建议也随实际可用工具调整。

**3. TASKS.md 按会话隔离**（`tools/tasks.js`）

账本默认路径曾是固定的 `TASKS.md`，同一工作目录下的所有会话共用同一个文件，
并行时互相覆盖目标/阶段/任务 —— 表现为「每个会话最后都变成同一个会话」。

现在默认 `.dsh/tasks/<sessionId>.md`：同会话跨轮次/跨重启稳定，不同会话互不干扰，
仍在工作区内便于查看；拿不到 `sessionId` 时安全退回 `TASKS.md`。

**4. DSH 0.2.2-rc.2 兼容**

- `{{cwd}}` 已从提示词变量白名单移除（只剩 `provider` / `model`），引用了它的 persona
  后缀会让整条预设挂载失败。现在全部改为纯文本。
- 预设不再重复挂载 `delegation` 组：`dsh-base` 已在全局提供 subagent / workflow，
  预设再挂一份只会「scoped 遮蔽 global」，且会造出第二个 `workflowEngine`。
  需要 `modelSelection` 的差异改为在 profile 层按 id 覆盖。

## 验证

19 个测试文件、183 项断言通过。新增：

| 测试 | 项数 | 覆盖 |
|---|---|---|
| `gate-reconcile` | 10 | 只裁剪不新增、幂等、undefined 不裁剪、全关清空、非受管预设不受影响 |
| `tasks-isolation` | 5 | 不同会话路径不同、同会话稳定、落在 `.dsh/tasks`、缺 sessionId 安全降级 |
| `tooling-ergonomics` | 14 | 动态求值、只放行 `FS_NOT_OBSERVED`、清单按实际注册渲染 |

## 升级

```bash
plugin_manager install_bundle <本目录 或 local-dsh-agentkit-1.7.0.tgz>
```

装完**重启一次** DSH Desktop。

> 旧的 `TASKS.md` 不会自动迁移。多会话共用过的那份需人工判断归属后再挪到
> `.dsh/tasks/<会话 id>.md`。
