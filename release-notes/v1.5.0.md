# 通用 agent 工具集 v1.5.0

`@local/dsh-agentkit` —— 与翻译、模型无关的通用 agent 工具集，以 DSH 的 bundle + agent preset 形式分发。

这一版修的是**工具层的行为缺陷**：`edit` 编辑 CRLF/LF 混排文件时，会把整份文件的行尾统一成一种风格。

## 问题

一个 2374 行的 CRLF/LF 混排文件（788 行 CRLF），只改一行之后，`git diff` 出现 **3252 行**改动 ——
真实语义改动只有 80 行左右，其余全是行尾噪声，审阅时无法分辨。

根因在 host 的 `fs.editText`：

```js
function detectLineEndings(raw) { /* 取前 4KB 的主导风格 */ }
function restoreLineEndings(content, lineEndings) {
  return lineEndings === "LF" ? content : normalizeLineEndings(content).split("\n").join("\r\n")
}
```

`readForEdit` 把内容归一成 LF 并**只记一个全局风格**，写回时再按这个风格把**整份文本**重新拼一遍。
`agentkit` 的 `edit` 对 UTF-8 本地文件走 `ctx.fs.editText` 的 fastPath，于是继承了这套「整文件单一风格」的语义。

## 修法

新增 `planEolPreservingEdit()`（`lib/encoding.js`）：**只替换命中区间**。

1. 把原文映射成「裸 LF」视图，同时记录每个字符回到原文的下标（`toLfView`）；
2. 模式归一成 LF 后在视图上查找 —— 因此 `old_string` 用哪种行尾写都能匹配；
3. 用偏移映射把命中区间换回原文下标，**只替换这一段**；
4. 替换文本内部的换行沿用**锚点行**的行尾（`eolAt`），不会制造新的混排；
5. 未命中的字符（包括每一行各自的行尾）**原字节保留**。

`edit` 检测到 `mixed` 时改走这条路径，写回使用既有的按字符集原子写（`encode_write.py`，二进制模式落盘，不做换行翻译）。

效果：真实改动 = diff。上面那个文件现在只差 80 行。

## 验证

新增 `test/eol-mixed.test.mjs`（13 项），覆盖：混排识别、偏移映射、锚点行尾选择、单行编辑保字节、
delete、`replace_all` 跨两种行尾、模式风格容错、未命中不动文件、2400 行文件只改一处时前后逐字节相同。

全套 16 个测试文件全部通过。

## 已知限制

- `write` 是整文件写入，仍然沿用文件的主导风格（这是有意为之：整体重写时没有「锚点」可言）。
  要保住混排行尾请用 `edit`。
- 混排文件不再走 `ctx.fs.editText` fastPath，写回改经 Python 助手（约百毫秒级），文件名不变、内容按原字符集。
